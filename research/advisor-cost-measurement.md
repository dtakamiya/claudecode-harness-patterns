# Advisor ツールの費用・呼び出し頻度の実測

実測日: 2026-11-14 / 対象: Claude Code 2.1.325、`claude -p`（ヘッドレス）/ 総費用 $6.4（本番 30 回）＋試走約 $1

## 結論

- 呼び出しを指示しなければ、Advisor は **10 回中 0 回** 呼ばれなかった（本番 9 回＋試走 1 回）。費用は Sonnet 単独と差がない（+9%、ばらつきの範囲内）。
- 2 回呼ぶよう指示すると、1 件 **$0.72**。Sonnet 単独（$0.10）の **7.2 倍**、Opus 単独（$0.26）の **2.8 倍**。
- Advisor 1 回あたり約 **$0.25〜0.34**（Opus 分）。この難易度では、Opus 単独でタスクを丸ごと解く費用とほぼ同じ。
- 全構成が全問正解。このタスク群では Advisor の品質効果は測れない（天井効果）。
- 判断: Advisor は有効にしたままで損はない（呼ばれなければ費用はほぼゼロ）。ただし単純な作業で呼び出しを強制・推奨するのは割に合わない。

## 条件

- タスク: `tasks/t1`（slugify）、`t2`（TTLCache）、`t3`（cron next_run）。隠しテストで採点。
- effort: 全構成 `medium`。`--setting-sources project` でユーザーの settings.json（既定モデル・advisorModel など）を除外した。
- ユーザーの `~/.claude/CLAUDE.md` と `~/.claude/rules/` は除外できておらず、全構成に同じ内容が読み込まれていた（実行後に確認。ユーザー側のエージェント定義は読み込まれていない）。構成間の比較には影響しないが、他の環境では費用・挙動が変わりうる。
- Advisor の有効化: `--settings '{"advisorModel":"opus"}'`。デバッグログで `[AdvisorTool] Server-side tool enabled with claude-opus-5-5` を確認。
- 呼び出し回数: stream-json の `server_tool_use`（name=`advisor`）を数えた。
- 費用: `total_cost_usd`。Advisor 分は `modelUsage` の `claude-opus-5-5` に計上されることを確認。
- スクリプト: `_harness-bench-5-5/run_advisor_bench.py`、生データ: `_harness-bench-5-5/results_advisor.jsonl`

| 構成 | 内容 | 試行 |
|---|---|---|
| S | Sonnet 5.5 単独 | 3 タスク × 3 |
| SAn | Sonnet 5.5 + Advisor(Opus 5.5)、呼び出しはモデル任せ | 3 タスク × 3 |
| SAf | 同上、2 回呼ぶよう指示（上限の参考値） | 3 タスク × 1 |
| O | Opus 5.5 単独 | 3 タスク × 3 |

## 結果

| 構成 | 合格 | 費用 平均（最小〜最大） | S 比 | Advisor 呼び出し | 所要時間 平均 |
|---|---|---|---|---|---|
| S | 9/9 | $0.100（0.067〜0.136） | 1.0 | — | 32.7 秒 |
| SAn | 9/9 | $0.109（0.074〜0.132） | 1.09 | 0 回（9 回中） | 38.2 秒 |
| SAf | 3/3 | $0.721（0.638〜0.858） | 7.2 | 2 回 × 3 | 109.0 秒 |
| O | 9/9 | $0.261（0.176〜0.345） | 2.6 | — | 46.4 秒 |

SAf の内訳（Opus 分 = Advisor 2 回分）:

| タスク | 合計 | Sonnet 分 | Opus 分 | 1 回あたり |
|---|---|---|---|---|
| t1 | $0.638 | $0.148 | $0.490 | $0.245 |
| t2 | $0.668 | $0.161 | $0.507 | $0.253 |
| t3 | $0.858 | $0.180 | $0.678 | $0.339 |

## 解釈

- Advisor は呼ばれなければ費用がかからない。SAn と S の差（+$0.009）は、試行間のばらつき（S 内で $0.067〜0.136）より小さい。
- 1 回の呼び出しが高いのは、Advisor が会話全体を受け取って Opus で推論するため（試走 t3 で Opus 出力 8,758 トークン）。
- 呼び出しを強制すると Sonnet 側の費用も約 1.6 倍に増える（S 平均 $0.100 → SAf の Sonnet 分 平均 $0.163）（助言への対応で往復が増える）。
- 記事（claude.dev「Which Claude model should you build with?」）の「効果は consult rate 次第」「executor 単独を明確には上回らない」という指摘と矛盾しない。

## 限界

- 計測時のユーザー指示ファイル（`~/.claude/CLAUDE.md`、`~/.claude/rules/`）が読み込まれている。指示ファイルを除外する `--bare` は API キー認証が前提のため使っていない。
- 既存の `results.jsonl`（構成 A〜E）は指示ファイルを変更する前に実行しており、本計測の S と直接は比べられない。
- 構成 E（`run_bench.py`）の「advisor」は Opus のサブエージェントで、本計測の Advisor ツールとは別物。
- t1 の SPEC は計測後に型注釈を `int | None` から `Optional[int]` に直した（Python 3.9 で動かないため）。本計測の t1 は修正前の SPEC で実行した。

- 全構成が全問正解のため、品質の差は測れていない。Advisor が効くかは「Sonnet 単独で落ちるタスク」でしか分からない。
- ヘッドレス実行の結果。対話セッションでは Advisor の使い方を指示するシステムプロンプトが入る場合があり（例: 「作業前と完了前に呼ぶ」）、呼び出し頻度は SAn より SAf に近い可能性がある。未計測。
- 試行数は SAf が各 1 回、他が各 3 回。
