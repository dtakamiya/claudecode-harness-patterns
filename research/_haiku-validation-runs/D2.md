# D2 — 設計判断（2 パターン統合の是非）

プロンプト: `claude-code-lightweight-feature-harness/README.md` と
`claude-code-micro-bugfix-harness/README.md` を読み、統合すべきか判断。両論の根拠＋推奨 1 つ。

## Ground truth（両 README の実差異）

| 軸 | Lightweight Feature | Micro Bugfix |
|---|---|---|
| フロー | Intake→Explore→Micro Plan→TDD→Verify→2軸Review→Handoff | Triage→Reproduce→Fix→Verify→2軸Review→Report |
| 規模 | 概ね 3〜10 ファイル | 概ね 1〜3 ファイル（4 以上は昇格） |
| テスト | 受入条件の失敗テスト先行 | 不具合を再現する回帰テスト先行 |
| セキュリティ | security-reviewer が入力・権限・秘密情報 | 脆弱性と権限拡大＋**認証/認可/秘密情報/暗号/境界の変更は「向いていないケース」で明示除外** |
| PR | 規定なし | PR 作成依頼時のみ CodeRabbit コメント全解消 |
| 共通 | 単一セッション / 非 main ブランチ / baseline 記録 / 2軸Review + Human Review Evidence / progress.yaml・handoff 文書・常設 Agent なし / Change Intent Record | 同左 |

## 結果（全試行「統合しない」を推奨）

| 試行 | 所要 | tool_uses | 両論 | セキュリティ除外の把握 | CodeRabbit 条件 | 結論の一貫性 |
|---|---|---|---|---|---|---|
| haiku-1 | 50.0s | 2 | ✓ | ✓ 正確に指摘 | ✓ | ✓ しない＋共通ガイドライン doc |
| haiku-2 | 42.8s | 2 | ✓ | ✓ | ✓ | ✓ しない＋共通テンプレート別ファイル化 |
| haiku-3 | 44.2s | 2 | ✓ | ✓ | 言及なし | ✓ しない＋共通化 doc |
| sonnet-baseline | 77.1s | 6 | ✓ | ✓ | ✓ | ✓ しない＋共有リファレンス抽出 |

sonnet-baseline は指示範囲（README のみ）を超えて両 `design.md` §5〜§8 まで読み、
「7〜8 割が同一文面」「Human Review Evidence の YAML 例がほぼバイト一致」と定量化した。
Haiku は指示どおり README のみを読み、正しい対比を出した（design.md 未読は減点対象外）。

全 Haiku が「新機能追加 vs バグ修正」「TDD vs 回帰再現テスト」「規模帯」を正しく対比し、
Bugfix 側のセキュリティ境界の明示除外という細部も捉えた。推奨は 3 試行とも「統合しない＋
共通部分を別テンプレート化」で一致。
