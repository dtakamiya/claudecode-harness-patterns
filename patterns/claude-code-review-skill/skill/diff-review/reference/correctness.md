# 正当性・境界・並行性

差分に現れた変更に対して、以下を候補として拾う。**ここは候補出しであり、判定ではない。** 各候補はSKILL.md Step 4の反証を通すこと。

## 境界とオフバイワン

- ループの終端条件（`<` と `<=` の取り違え）
- インデックス計算、スライス範囲、先頭・末尾要素の扱い
- 切り上げ / 切り捨ての取り違え。特に**ページ数・チャンク数・バッチ数の算出**。`ceil` を意図した箇所が `floor`（整数除算）になっていないか
- 空コレクション、要素1件、上限ちょうどの入力
- 数値のオーバーフロー、精度欠落（浮動小数での金額計算、`int` への切り詰め）

反証の際は、**割り切れる値でなく割り切れない値**で失敗シナリオを書く。`total=10, per_page=10` では ceil と floor が一致し欠陥が発現しない。

## null / 未定義 / 例外

- 新たに導入された参照に対し、呼び出し経路上でガード節が存在するか
- Optional / nullable の剥がし方（`!` `unwrap()` `get()`）が安全か
- 例外の握りつぶし。ただし**コメントやテストで意図が明示されているなら欠陥ではない**
- リソース解放漏れ（ファイル、コネクション、ロック）。早期returnや例外経路を含めて確認する

## 呼び出し規約の不整合

差分に関数シグネチャの変更が含まれる場合、**呼び出し元を Grep で引く**（手順は SKILL.md Step 3）。

- 引数の順序変更に、呼び出し側が追随していない。**型が同じだと型検査器も通ってしまう**ため、これは静的解析で拾えない
- 引数の増減に対する呼び出し側の未更新
- 戻り値の型・意味の変更（真偽の反転、null を返すようになった等）に対する呼び出し側の未対応
- デフォルト引数の変更により、既存の呼び出しの挙動が変わる

## 制御フローと状態

- 早期returnの追加により後続処理が飛ばされていないか
- 条件分岐の追加で既存の分岐が到達不能になっていないか
- 変更されたメソッドが、呼び出し順序に依存する不変条件を壊していないか
- 初期化前の使用、初期化の二重実行

## 並行性

- 共有可変状態への非同期アクセス
- check-then-act（存在確認してから作成、残高確認してから減算）の非原子性
- ロックの取得順序の不一致によるデッドロック
- async/await の抜け（awaitし忘れ、fire-and-forgetの意図せぬ導入）

**反証時の必須確認**: 当該コードが実際に複数スレッド・複数リクエストから到達するか。呼び出し元が単一スレッドに限定されているなら、競合状態は**到達不能として棄却する**。これは典型的な偽陽性経路である。

## エラーハンドリングの契約

- 戻り値でエラーを返す関数の呼び出し側が、それを無視していないか
- 再試行に冪等性が必要な操作で、冪等でないものを再試行していないか
- タイムアウトのない外部呼び出し

## データ整合性

- トランザクション境界の内外の取り違え
- 部分的な失敗時のロールバック
- キャッシュの無効化漏れ（更新はするが古い値が残る）
